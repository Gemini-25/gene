## 실험에서 알게 된 것

1. **번식 시각이 신생아 생존을 정한다(E1-b).** 오후에 태어난 자식은 첫 밤을 거의 넘기지 못한다. 오전에만 번식을 시작하는 Founder-6은 오전 출생 비율을 4.7%에서 54%로 옮겼고, 개체 수가 한때 7,000 가까이 늘었다.
2. **탄소가 죽은 유기물에 갇힌다(E1-c).** 생존 온도에서 G 분해(Rx2)가 거의 없다. 그래서 개체 수가 커질수록 공기의 C가 줄고 광합성이 준다. 버려진 코드 기록(G 페이지)도 같은 역할을 한다. 변이가 생긴 출생 때마다 변이 전 사본 5 페이지가 땅에 버려진다.
3. **죽은 G를 다시 먹는 행동이 탄소를 되돌린다(P1 소규모, E1-d 확인 중).**
4. **M1 기능은 변이만으로는 발견되지 않았다(P1).** 소규모 4 seed에서 m0와 m1d 결과가 완전히 같았다.
5. **변이를 막는 계통이 저절로 생긴다(E1-c).** Step 대신 Resize를 부르는 1 bit 변이체는 변이가 계획된 배아를 끝내지 못한다. 그래서 정확한 사본만 남긴다. 소수로 40일 넘게 유지됐지만 퍼지지는 않았다.

## 결정이 필요한 것

### 1. E2: M1 기능을 어떻게 시험할 것인가

| 선택지 | 내용 | 비용·위험 |
| --- | --- | --- |
| A. 큰 규모에서 변이만으로 | Founder-7 + `gene-m1-4`, 512², 20 seed | 규칙 변화 없음. P1 결과로 보아 0일 가능성이 큼 |
| B. M1 기능을 쓰는 조상 | 예: 자기 코드를 공개 기록으로 남기고 근처 기록을 학습하는 조상. 또는 밤에 차폐 구조물에 들어가는 조상 | 조상 편향을 공개해야 함. "기능이 유지·확산되는가"를 물을 수 있음 |
| C. 변이 연산 확장 | 모듈 재조합, 무작위 명령 삽입 | 새 규칙. SPEC §21 증거 규칙의 기록이 먼저 필요 |

추천: B. 원본의 질문(정보가 세대를 넘어 전달·축적되는가)에 직접 답할 수 있다. 다만 어떤 기능을 조상에게 줄지는 연구 방향 결정이라 사용자가 정한다.

### 2. 탄소 순환을 행동으로 둘 것인가, 물리로 고칠 것인가

- 지금은 원본 그대로다. 분해는 느리고, 재활용은 개체의 행동(Founder-7)에 맡긴다.
- 대안은 새 ruleset에서 생존 온도의 Rx2 속도를 올리는 것이다. 그러려면 증거 규칙을 따라야 한다. 막힌 경로의 기록(E1-c)은 이미 있다. "추가하지 않는 대안"으로 Founder-7을 시험 중이다.
- 추천: E1-d 결과를 보고 정한다. Founder-7로 개체 수가 안정되면 물리는 그대로 둔다.

### 3. 원본에서 아직 구현하지 않은 범위

- 관찰층: 관계 graph, artifact 동일성, 복사 계보(원본 §58). 구조물·기록을 쓰는 행동이 나타나면 의미가 생긴다.
- 역사 되감기(원본 §40), Bevy 화면(원본 §37). 지금은 웹 viewer로 대신한다(D15).
- Matter-1 이후의 연구 부록(형상 역학, 일반 화학, 전기 등). 증거 규칙을 통과해야 들어온다.

### 4. 성능

- 512² 단일 thread 약 190 TPS로, 명세 목표 S1(500+)에 못 미친다.
- 병렬 단계는 결과가 같지만, 측정은 실험이 CPU를 다 쓰고 있어 미뤘다.
- 비용의 대부분은 수송 단계의 정확한 정수 연산과 Philox 난수다. 결과를 바꾸지 않는 최적화로는 큰 개선이 어렵다.
